# Company Vision (Parked)

Recorded November 8, 2026. Status: parked. Not part of the current roadmap. The Monarch will expand this vision later; until then, do not build toward it beyond keeping the design open to more roles.

## The Idea

shadowarmy should eventually work like a whole software company with one human, delivering any software from idea to launch and beyond, the way a SaaS company would.

## Possible Departments

| Department | Delivers |
| --- | --- |
| Product | Specs from ideas: users, features, scope, definition of done |
| Design | User flows, UI designs, a design system |
| Engineering | Architecture, code and tests (today's Marshal, Soldiers and Knight) |
| QA | End-to-end verification (today's Scout) |
| DevOps | CI/CD, hosting, databases, domains, monitoring |
| Docs | READMEs, user guides, API references |
| Launch | Landing page, release notes, announcement copy |
| Support and maintenance | Bug intake, dependency updates, fixes after launch |
| Operations | Budget, progress reporting, stuck-work alerts (today's Sentinel) |

## Constraints To Remember

- Anything involving accounts, money or legal identity (hosting, payments, domains, app stores) needs the Monarch to provide access once.
- Each new department should be one more role with the same contract style as [roles](roles.md): files in, schema-validated files out, deterministic scripts around it.

## Questions For The Monarch

1. Who is the customer: only the Monarch, or other people bringing ideas?
2. What does "delivered" mean: a repository, a deployed live app, or ongoing maintenance?
3. Which departments matter first?
4. How involved does the Monarch want to be: plan and launch only, or every pull request?
